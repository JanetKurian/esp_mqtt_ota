1. INTRODUCTION
1.1 Purpose
This document describes the software design of the STM32F303RE-based LTE MQTT Communication Firmware using the EG800EU LTE Cellular Module. It presents the layered software architecture, module responsibilities, task design, and execution flow that enable cellular network connectivity and MQTT-based publish and subscribe communication.
1.2 Scope
This document covers the software architecture of the STM32F303RE LTE MQTT Communication Firmware, including the Application, Middleware, and Hardware Abstraction (HAL) layers. It describes the cellular communication over UART, MQTT session management, application packet publishing and processing, FreeRTOS task organization, software execution flow, startup sequence, and the interaction between the firmware modules.
1.3 Overview
The firmware enables cellular communication between the STM32F303RE microcontroller and an MQTT broker using the EG800EU LTE Cellular Module. It establishes cellular network connectivity, creates and maintains an MQTT client session, publishes application data, subscribes to MQTT topics, and processes incoming MQTT messages. The firmware is implemented using a layered software architecture with FreeRTOS for task management and STM32 HAL for hardware abstraction.

1.4 References
The software design described in this document is based on the STM32F303RE microcontroller, the EG800EU LTE Cellular Module, STM32 HAL libraries, FreeRTOS, and the MQTT communication protocol. The firmware implementation follows the corresponding hardware reference manuals, software libraries, and AT command ajax

2. System Overview
The STM32F303RE LTE MQTT Communication Firmware provides a reliable communication interface between the embedded system and a remote MQTT broker using the EG800EU LTE Cellular Module. The firmware communicates with the cellular module over a UART interface using AT commands to establish cellular network connectivity and create an MQTT client session. Once connected, it supports bidirectional MQTT communication by publishing application data and processing subscribed messages received from the broker. The software is organized into Application, Middleware, and Hardware Abstraction (HAL) layers to provide a modular, maintainable, and scalable firmware architecture.

2.1 Hardware Overview
The firmware is designed to run on the following hardware platform:
•	STM32F303RE microcontroller
•	EG800EU LTE Cellular Module
•	UART interface between the STM32F303RE and the EG800EU module




2.2 System Block Diagram
The system consists of the STM32F303RE microcontroller interfaced with the EG800EU LTE Cellular Module through a UART communication interface, as shown in the block diagram. The STM32 communicates with the cellular module using AT commands over UART to control network operations and establish LTE connectivity. The EG800EU module then connects to the MQTT broker over the cellular network. This setup enables bidirectional communication by transmitting application data to the broker and receiving subscribed MQTT messages for processing.


 

Figure 1: System Block Diagram

2.3 Software Architecture Overview
The firmware follows a three-layer software architecture consisting of the Application Layer, Middleware Layer, and Hardware Abstraction Layer (HAL). This layered approach separates application functionality, communication services, and hardware-dependent drivers, resulting in a modular, maintainable, and scalable firmware design.
The Application Layer implements the firmware logic responsible for cellular initialization, MQTT communication, application data handling, and packet processing. The Middleware Layer provides common software services, including FreeRTOS task management, AT command processing, UART response parsing, software timers, and firmware state management. The Hardware Abstraction Layer (HAL) provides the UART driver interface used for communication between the STM32F303RE microcontroller and the EG800EU LTE Cellular Module.

4. Detailed Layer Description
4.1 Application Layer
The Application Layer contains the main firmware logic for cellular and MQTT communication. It is responsible for initializing the EG800EU cellular module, establishing the MQTT connection, publishing application data, subscribing to MQTT topics, and processing received MQTT messages. This layer uses the services provided by the Middleware Layer to perform all communication with the EG800EU cellular module.


4.1.1 Application Layer Architecture
The Application Layer is organized into individual modules, where each module is responsible for a specific part of the cellular and MQTT communication process. Together, these modules initialize the cellular module, establish the MQTT connection, publish application data, receive subscribed MQTT messages, and process the received MQTT data.

 

Figure 4: Application Layer Architecture 

The Application Layer consists of the following modules:
•	Cellular Application
•	MQTT Application
•	Publish Logic & Application Data Handling
•	MQTT Packet Processing

4.1.2 Module Descriptions

Cellular Application
The Cellular Application is responsible for initializing the EG800EU cellular module and preparing it for MQTT communication. It sends the required AT commands to verify the SIM status, network registration, and data connectivity. Once all the checks are completed successfully, the firmware proceeds to establish the MQTT connection.

5. Task Description
5.1 Cellular Task
The Cellular Task is the main FreeRTOS task in the firmware. It runs continuously after the system initialization is completed and handles the MQTT communication during normal operation. The task processes received MQTT messages, executes scheduled data publishing, and monitors the communication status throughout the system operation.

6. Firmware State Machine
The firmware follows a state-based execution model to control the initialization sequence and normal runtime operation. Each state represents a specific stage of the firmware, and the system transitions to the next state only after the current operation completes successfully. This approach simplifies firmware execution, improves readability, and provides a structured method for handling communication and error conditions.


State	Description	Next State
APP_STATE_INIT	Initializes the STM32 peripherals and FreeRTOS kernel.	APP_STATE_CHECK_CELLULAR
APP_STATE_CHECK_CELLULAR	Verifies SIM status, network registration, and packet data connectivity.	APP_STATE_MQTT_DEINIT
APP_STATE_MQTT_DEINIT	Bring the Module to the Know State(Initial state)	APP_STATE_MQTT_INIT
APP_STATE_MQTT_INIT	Establishes the MQTT connection with the broker.	APP_STATE_MQTT_SUBSCRIBE
APP_STATE_MQTT_SUBSCRIBE	Subscribes to the required MQTT topics.	APP_STATE_RUNNING
APP_STATE_RUNNING	Publishes application data and processes received MQTT packets.	APP_STATE_RUNNING
APP_STATE_ERROR	Entered when initialization fails.	APP_STATE_INIT

8. Memory Usage Overview
The firmware uses static memory allocation for communication buffers, application data structures, and the FreeRTOS task stack to ensure predictable memory usage during runtime. Communication buffers are allocated at compile time and reused throughout execution, reducing memory fragmentation and improving system reliability. Dynamic memory allocation is limited to JSON object creation and parsing during MQTT packet construction and processing.

Resource	Size	Purpose

Command formatting buffer	1024 bytes	Used to format outgoing AT commands
Publish command buffer	512 bytes	Used to format outgoing publish command strings
JSON payload buffer	1024 bytes	Holds the serialized JSON payload prior to transmission
Application packet structures	Variable	Hold the data fields for each application packet type prior to publishing
Application task stack	720 words	Stack allocated to the single FreeRTOS application task
